# Отложенное проведение документов

Подсистема `пбп_ОтложенноеПроведениеДокументов` ставит документ в очередь проведения одним вызовом. Регламентное задание проводит порцию очереди. Состав регистров конфигурации-потребителя при этом не меняется.

Измерение `Объект` регистра очереди имеет тип `пбп_ОбъектОтложенногоПроведения`. В каркасе в него входит `ДемоРаботаСФормами`. Конфигурация-потребитель добавляет в этот определяемый тип свои документы. Пока тип не равен набору «любая ссылка на документ», добавление постороннего документа не перестраивает регистр.

Версия библиотеки с этим интерфейсом — `1.0.11.0`.

## Включение

1. Установить константу `пбп_ИспользоватьОтложенноеПроведениеДокументов` (функциональная опция с тем же именем). По умолчанию опция выключена.
2. Включить предопределённое регламентное задание `пбп_ОтложенноеПроведениеДокументов`. В поставке у него `Использование = Ложь`. Метод задания — `пбп_МетодыРегламентныхЗаданийСервер.ОтложенноеПроведениеДокументов`.
3. Роль `пбп_ЧтениеОтложенногоПроведенияДокументов` даёт просмотр списка очереди. Форма списка только для чтения.

Пока опция выключена, `ЗапланироватьПроведение` вызывает исключение и ничего не записывает. Задание в этом случае сразу завершается.

## Программный интерфейс

Модуль `пбп_ОтложенноеПроведениеДокументов`:

- `ПараметрыОтложенногоПроведения(Ссылка)` — структура параметров. Пустые `ВремяОжидания`, `ШагУвеличенияОжидания` и `МаксимумПопыток` (`Неопределено`) при записи не меняют настройку вида документа. Незаданные поля читаются из общей настройки в момент проведения.
- `ЗапланироватьПроведение(Параметры)` — идемпотентная постановка. Счётчик попыток сохраняется, если не передан `СброситьПопытки`. Повторная постановка снова делает строку активной.
- `ОтменитьОтложенноеПроведение(Ссылка)` — удаляет строку очереди.
- `СостояниеОтложенногоПроведения(Ссылка)` — `Неопределено` или структура: `Активна`, `КоличествоПопыток`, `ДатаСледующейПопытки`, `ТекстОшибки`, `ОбработкаПрекращена`.
- `ОтложенноеПроведениеДокументов()` — тело регламентного задания.

Для формы с клиента то же состояние возвращает `пбп_ОтложенноеПроведениеДокументовВызовСервера.СостояниеОтложенногоПроведения`.

```bsl
Параметры = пбп_ОтложенноеПроведениеДокументов.ПараметрыОтложенногоПроведения(Ссылка);
Параметры.Перепроведение = Истина;
Параметры.ОбработчикПослеПроведения = "МойМодуль.ПослеОтложенногоПроведения";
пбп_ОтложенноеПроведениеДокументов.ЗапланироватьПроведение(Параметры);
```

Если в параметрах заданы время ожидания, шаг или максимум попыток, в настройку вида документа пишутся только эти поля. Остальные по-прежнему берутся из общей строки.

## Обработчик

Экспортная процедура `Модуль.Процедура(Объект, Контекст)`. Вызов идёт через `пбп_Переадресация.ВыполнитьМетодКонфигурации`.

Поля `Контекст`:

| Поле | Смысл |
| --- | --- |
| `Перепроведение` | Провести уже проведённый документ |
| `ДополнительныеПараметры` | Значение, прочитанное из JSON |
| `НомерПопытки` | Номер текущей попытки |
| `ЭтоПоследняяПопытка` | Эта попытка достигает максимума |
| `ТребуетсяПроведение` | Обработчик «перед» может отменить запись |
| `ВыполнитьКонтрольЗаполнения` | Вызывать `ПроверитьЗаполнение` |
| `РежимЗаписи` | По умолчанию `РежимЗаписиДокумента.Проведение` |
| `ТекстОшибки` | Текст ошибки, для обработчика ошибки |
| `ПрекратитьПопытки` | Снять документ с дальнейших попыток |
| `ДатаСледующейПопытки` | Если заполнена обработчиком ошибки, подменяет расчётный сдвиг |

`ДополнительныеПараметры` — структура, массив, соответствие, примитивы и ссылки. Ссылки упаковываются в JSON и восстанавливаются.

Обработчик «после» вызывается только после успешной записи. В ветке ошибки вызывается только обработчик ошибки, уже вне транзакции документа.

## Настройки

Регистр `пбп_НастройкиОтложенногоПроведения`, измерение `ИмяДокумента`. Пустое имя — общая настройка.

Задание собирает значения так: общая строка (или `0 / 0 / 3`, если её нет), затем поверх неё только те поля строки вида документа, у которых признак «задано» равен истине. Пауза и шаг — в секундах.

Сдвиг следующей попытки: `пауза + шаг * номер попытки` секунд от момента ошибки. На третьей ошибке при максимуме 3 строка получает `ОбработкаПрекращена`.

## Прогон задания

1. Опция выключена — выход.
2. Порция 50 строк по дате следующей попытки, затем по дате добавления: дата следующей попытки наступила, обработка не прекращена, нет захвата моложе 10 минут.
3. На строку — исключительная блокировка по документу и отметка захвата.
4. В транзакции документа: пометка удаления или проведённый документ без перепроведения снимаются с очереди. Иначе — обработчик «перед», проверка заполнения, `Записать`, обработчик «после», удаление строки. В дополнительные свойства объекта пишется `пбп_ОтложенноеПроведение = Истина`.
5. При ошибке транзакция документа откатывается. Затем, вне её, вызывается обработчик ошибки, счётчик увеличивается, дата сдвигается, при максимуме обработка прекращается, захват снимается.

Привилегированный режим включается на время задания и на запись служебных регистров из программного интерфейса.

## Запрет правки

Подписка `пбп_ДокументыПередЗаписью` для документа вызывает `пбп_ДокументыОбработкаСобытий.ПередЗаписью`. Активная строка очереди и отсутствие свойства `пбп_ОтложенноеПроведение` дают отказ и сообщение пользователю. Обмен данными и выключенная опция запись не блокируют. Прекращённая обработка правку снова разрешает.

## Ограничения

В регистре не хранится и не выполняется строка кода. Обработчик — только имя экспортной процедуры. Очередь не обходит блокировки и не обрабатывает всю таблицу за один проход. Перенос данных из `АИТ_ОтложенноеПроведениеДокументов` в эту очередь — отдельная задача.

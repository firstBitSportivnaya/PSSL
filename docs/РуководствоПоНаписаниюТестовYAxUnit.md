# Руководство по написанию тестов YAxUnit

Ветка расширения в репозитории: `src/cfe/YAXUnit` (имя метаданных `YAXUNIT`).  
Актуальная версия движка в дампе: **25.12** (см. `Configuration.xml` → `Version`).

Канон возможностей и API — официальная документация:

- [Возможности YAxUnit](https://bia-technologies.github.io/yaxunit/docs/features)
- [Регистрация тестовых методов](https://bia-technologies.github.io/yaxunit/docs/features/test-registration)
- [Сайт YAxUnit](https://bia-technologies.github.io/yaxunit/)

Ниже — правила проекта ПБП поверх этой документации.

## Подготовка окружения

1. Клонировать репозиторий и загрузить основную конфигурацию из `src/cf/`.
2. Загрузить расширение из `src/cfe/YAXUnit` (source-set `YAXUNIT`). Не смешивать с артефактом `tools-download` yaxunit.
3. В режиме 1С:Предприятие должна появиться панель/подсистема YAxUnit.
4. Параметры пакетного прогона CI: `tools/yaxunit.json` (отчёт `./build/out/yaxunit/`).

Локальная загрузка в ИБ и прогон через Unica — skill `pssl-library` (отдельный `build` для `main`, затем `YAXUNIT`; `testRunner=yaxunit`).

## Соглашения ПБП

| Правило | Деталь |
|--------|--------|
| Имя модуля | `ОМ_<Объект>` — по тестируемому объекту/модулю ядра (`ОМ_ПредопределенныеЗначения`, `ОМ_КоннекторHTTP`, …). Один подчёркивающий символ после `ОМ`. |
| Где лежит код | Только в `src/cfe/YAXUnit`, не в `src/cf`. |
| Движок `ЮТ*` | Не править без явной задачи на обновление YAxUnit. |
| Данные | Предпочтительно создавать программно через `ЮТест.Данные()`, а не вручную в ИБ. |
| Типы в утверждениях | Для типа значения использовать `ТипЗнч(...)`, не путать с конструктором `Тип(...)`. |
| Предикаты «пусто» | В 25.x канон — `НеЗаполнено()`; `Пусто()` оставлен как алиас совместимости, в новых тестах не использовать. |

### Флаги общего модуля теста

Для модулей `ОМ_*`, которые гоняются пакетным YaXUnit (сервер / внешнее соединение):

- `Server = true`
- `ExternalConnection = true` (если тест участвует в прогоне через внешнее соединение)
- `ClientManagedApplication = false`, `ClientOrdinaryApplication = false` — если тест не рассчитан на клиентский контекст

Иначе модуль может не попасть в нужный контекст исполнения, и набор в jUnit окажется пустым или неполным.

## Минимальный рабочий пример

Допустим в ядре есть функция:

```bsl
Функция ЧетноеЧисло(Число) Экспорт
	Возврат Число % 2 = 0;
КонецФункции
```

### 1. Модуль `ОМ_ОбщегоНазначенияВспомогательныеФункции`

Экспортная процедура `ИсполняемыеСценарии` **только регистрирует** тесты (без создания данных и инициализации ИБ) — см. [документацию](https://bia-technologies.github.io/yaxunit/docs/features/test-registration):

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты.ДобавитьТестовыйНабор("Проверка функции ЧетноеЧисло")
		.ДобавитьТест("ТестЧетноеЧисло")
			.СПараметрами(2, Истина)
			.СПараметрами(1, Ложь)
			.СПараметрами(0, Истина)
			.СПараметрами(-1, Ложь);

КонецПроцедуры
```

Имя в `ДобавитьТест` должно совпадать с именем экспортной процедуры теста.

### 2. Тело теста

Точка входа API — модуль `ЮТест` ([обзор возможностей](https://bia-technologies.github.io/yaxunit/docs/features)):

```bsl
Процедура ТестЧетноеЧисло(Число, ОжидаемыйРезультат) Экспорт

	Результат = пбп_ОбщегоНазначенияВспомогательныеФункции.ЧетноеЧисло(Число);
	ЮТест.ОжидаетЧто(Результат).Равно(ОжидаемыйРезультат);

КонецПроцедуры
```

Параметры `СПараметрами` передаются в тест **позиционно** (как в API `ЮТТесты`), а не одной структурой — если нужен именованный набор кейсов, используйте `ЮТест.Варианты(...)` внутри теста (см. `ОМ_ПостроительСпецификацииOpenAPI`).

## Что ещё доступно в движке (кратко)

Ориентир — [features](https://bia-technologies.github.io/yaxunit/docs/features):

- `ЮТест.Данные()` — конструкторы объектов, пустышки, макеты, HTTP-запрос, временные файлы, подражатель
- `ЮТест.ОжидаетЧто()` / `ЮТест.ОжидаетЧтоТаблицаБазы()` — утверждения
- `ЮТест.Предикат()`, `ЮТест.Варианты()`, `ЮТест.Контекст()`
- `Мокито` — подмена поведения методов, статистика вызовов
- Настройки регистрации: `.ВТранзакции()`, `.УдалениеТестовыхДанных()`, `.Перед()` / `.После()`, клиентский/серверный тест

Живые примеры в этом репозитории: модули `ОМ_*` в `src/cfe/YAXUnit/CommonModules/`.

## Прогон

- Интерактивно: подсистема YAxUnit в 1С:Предприятие.
- Пакетно (агент/CI): Unica `operation=test`, `testRunner=yaxunit`, `testScope=all` или `module` + `CommonModule.ОМ_…` (см. `pssl-library`).

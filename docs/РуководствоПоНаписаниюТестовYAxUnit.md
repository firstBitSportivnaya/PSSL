# Руководство по написанию тестов YAxUnit (PSSL)

Соглашения репозитория **Проектная библиотека подсистем (ПБП / PSSL)** для юнит-тестов на [YAxUnit](https://bia-technologies.github.io/yaxunit/).

- Дамп расширения: `src/cfe/YAXUnit` (имя в метаданных — `YAXUNIT`, source-set `YAXUNIT`).
- Версия движка в дампе: **25.12** (`Configuration.xml` → `Version`). Не путать с артефактом `tools-download` yaxunit.
- Канон API — в официальной документации; здесь только правила и примеры этого репозитория.

Документация движка:

- [Регистрация тестов](https://bia-technologies.github.io/yaxunit/docs/features/test-registration)

- [Запуск и отладка](https://bia-technologies.github.io/yaxunit/docs/getting-started/run/)

Локальная загрузка в ИБ и пакетный прогон — skill `pssl-library`.

## Подготовка окружения

1. Клонировать репозиторий и загрузить основную конфигурацию из `src/cf/` (source-set `main`).
2. Загрузить расширение из `src/cfe/YAXUnit` (source-set `YAXUNIT`). После загрузки снять **безопасный режим** и **защиту от опасных действий**.
3. Пути ИБ и платформы — только в `.dev.env` / `v8project.local.yaml` (не в Git).
4. Параметры CI: `tools/yaxunit.json` (фильтр по расширению `YAXUNIT`, отчёт jUnit в `./build/out/yaxunit/`).

В 1С:Предприятие должна быть доступна подсистема YAxUnit.

## Соглашения ПБП

| Правило | Деталь |
|--------|--------|
| Где писать | Только в `src/cfe/YAXUnit`, не в `src/cf`. Новый общий модуль расширения, не заимствование. |
| Имя модуля | `ОМ_<ОбъектБезПрефиксаПбп>` — один `_` после `ОМ`. Пример: `пбп_СтроковыеФункцииКлиентСервер` → `ОМ_СтроковыеФункцииКлиентСервер`. Без суффикса `_Тесты` и без `пбп_` в имени теста. |
| Движок `ЮТ*` | Не править без явной задачи на обновление YAxUnit. |
| Регистрация | Только в `ИсполняемыеСценарии()` через `ЮТТесты`. Без создания данных и инициализации ИБ в этой процедуре. |
| Данные | Предпочтительно `ЮТест.Данные()` программно, не ручное наполнение ИБ. |
| Типы | Для типа значения — `ТипЗнч(...)`, не конструктор `Тип(...)` (иначе «Тип не определен»). |
| «Пусто» | В 25.x — `НеЗаполнено()`; `Пусто()` — алиас совместимости, в новых тестах не использовать. |
| Параметры | `.СПараметрами(...)` — **позиционно**. Именованные наборы — `ЮТест.Варианты(...)` внутри теста (см. `ОМ_ПостроительСпецификацииOpenAPI`). |

Существующие наборы: `ОМ_КоннекторHTTP`, `ОМ_ПредопределенныеЗначения`, `ОМ_ПостроительСпецификацииOpenAPI`, `ОМ_СтроковыеФункцииКлиентСервер` и др. в `src/cfe/YAXUnit/CommonModules/`.

### Флаги общего модуля теста

Типичный серверный `ОМ_*` для пакетного YaXUnit (Enterprise / внешнее соединение):

| Свойство | Значение |
|---|---|
| `Server` | `true` |
| `ExternalConnection` | `true` |
| `ClientManagedApplication` | `false` |
| `ClientOrdinaryApplication` | `false` |
| `ServerCall` | `false` (кроме отдельных обёрток вызова сервера) |
| `Global` / `Privileged` | `false` |

Связь API регистрации и метаданных:

- `ДобавитьКлиентскийТест` / `ДобавитьСерверныйТест` выбирают контекст **только среди доступных модулю по флагам**.
- Для клиентских тестов нужны включённые `ClientManagedApplication` и/или `ClientOrdinaryApplication`.
- `Server` / `ExternalConnection` сами по себе клиентский запуск не дают.
- Не копировать клиентские флаги с исходного клиент-серверного модуля ядра «на автомате».

Иначе модуль может не попасть в нужный контекст, и набор в jUnit окажется пустым или неполным.

## Точка входа

```bsl
#Область СлужебныйПрограммныйИнтерфейс

Процедура ИсполняемыеСценарии() Экспорт
	// только регистрация через ЮТТесты
КонецПроцедуры

#КонецОбласти

#Область Тесты

// экспортные процедуры тестов — имя совпадает с ДобавитьТест(...)

#КонецОбласти
```

## Минимальный пример

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты.ДобавитьТестовыйНабор("Проверка функции ЧетноеЧисло")
		.ДобавитьТест("ТестЧетноеЧисло")
			.СПараметрами(2, Истина)
			.СПараметрами(1, Ложь)
			.СПараметрами(0, Истина);

КонецПроцедуры

Процедура ТестЧетноеЧисло(Число, ОжидаемыйРезультат) Экспорт

	Результат = пбп_ОбщегоНазначенияВспомогательныеФункции.ЧетноеЧисло(Число);
	ЮТест.ОжидаетЧто(Результат).Равно(ОжидаемыйРезультат);

КонецПроцедуры
```

## Пример из репозитория

Ориентир: `ОМ_СтроковыеФункцииКлиентСервер` (тесты `ПреобразоватьДатуИзСтрокиПоФормату`).

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.ДобавитьТестовыйНабор("ПреобразоватьДатуИзСтрокиПоФормату (0_0_0)")
			.ДобавитьТест("ТестДолженПарситьISOБезМиллисекунд")
			.ДобавитьТест("ТестДолженВозвращатьПустуюДатуПриНекорректномISO")
			.ДобавитьТест("ТестДолженВозвращатьПустуюДатуПриНечисловомКомпонентеISO");

КонецПроцедуры

Процедура ТестДолженПарситьISOБезМиллисекунд() Экспорт

	ИсходнаяСтрока = "2024-01-02T03:04:05";
	ОжидаемаяДата = Дата(2024, 1, 2, 3, 4, 5);

	Результат = пбп_СтроковыеФункцииКлиентСервер.ПреобразоватьДатуИзСтрокиПоФормату(ИсходнаяСтрока, "0_0_0");

	ЮТест.ОжидаетЧто(ТипЗнч(Результат)).Равно(Тип("Дата"));
	ЮТест.ОжидаетЧто(Результат).Равно(ОжидаемаяДата);

КонецПроцедуры
```

Утверждения — через `ЮТест.ОжидаетЧто(...)`. Для транзакционных сценариев с данными — `.ВТранзакции()` / `.УдалениеТестовыхДанных()` при регистрации.

## Что покрывать

- Happy path.
- Пограничные и некорректные входы — ожидаемое безопасное поведение API (часто пустая дата / исключение по контракту).
- Регрессии по известным дефектам.
- Не называть тест «веб-клиентским», если он не исполняется в веб-контексте (ветка `#Если Не ВебКлиент` vs `#Иначе` может отличаться).

## Возможности движка (кратко)

- `ЮТест.Данные()` — объекты, пустышки, макеты, HTTP-запрос, файлы, подражатель
- `ЮТест.ОжидаетЧто()` / `ЮТест.ОжидаетЧтоТаблицаБазы()`
- `ЮТест.Предикат()`, `ЮТест.Варианты()`, `ЮТест.Контекст()`
- `Мокито` — подмена методов и статистика вызовов
- Регистрация: `.Перед()` / `.После()`, клиентский/серверный тест

Подробнее — [features](https://bia-technologies.github.io/yaxunit/docs/features), [мокирование](https://bia-technologies.github.io/yaxunit/docs/features/mocking/), [тестовые данные](https://bia-technologies.github.io/yaxunit/docs/features/test-data/).

## Прогон

1. После правок BSL: отдельный `build` source-set `main` (если менялось ядро), затем `YAXUNIT`. Не один `build` «на все расширения».
2. Интерактивно — подсистема YAxUnit в 1С:Предприятие.
3. Пакетно (Unica): `operation=test`, `testRunner=yaxunit`, `testScope=all` или `module` с именем `ОМ_…` (см. `pssl-library`).  
   В фильтре YaXUnit часто достаточно имени модуля без префикса `CommonModule.`.

Закрыть клиент/конфигуратор перед `build` — Designer занимает ИБ эксклюзивно.

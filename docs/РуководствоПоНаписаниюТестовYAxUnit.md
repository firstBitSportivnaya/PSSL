# Руководство по написанию тестов YAxUnit (PSSL)

Документ описывает соглашения репозитория **Проектная библиотека подсистем (ПБП / PSSL)** при написании юнит-тестов на [YAxUnit](https://bia-technologies.github.io/yaxunit/).  
В дампе расширения (`src/cfe/YAXUnit`) — версия движка **25.12**.  
Канон API: [возможности](https://bia-technologies.github.io/yaxunit/docs/features), [регистрация](https://bia-technologies.github.io/yaxunit/docs/features/test-registration). Здесь — локальные правила и примеры из `src/cfe/YAXUnit`.

## Подготовка окружения

1. Клонируйте репозиторий:

```bash
git clone https://github.com/firstBitSportivnaya/PSSL.git
```

2. Загрузите основную конфигурацию из `src/cf` в информационную базу.
3. Загрузите расширение тестов из `src/cfe/YAXUnit` (имя расширения в метаданных — `YAXUNIT`).
4. После загрузки расширения снимите **безопасный режим** и **защиту от опасных действий** (см. [установку YAxUnit](https://bia-technologies.github.io/yaxunit/docs/getting-started/install/)).
5. Локальные пути ИБ и платформы — только в `.dev.env` / `v8project.local.yaml` (не в Git).

В режиме 1С:Предприятие должна быть доступна подсистема YAxUnit.

Параметры пакетного прогона: `tools/yaxunit.json` (фильтр по расширению `YAXUNIT`, отчёт jUnit). Запуск через Unica: `operation=test`, `testRunner=yaxunit` (см. skill `pssl-library`).

## Где писать тесты

- Только в расширении **`src/cfe/YAXUnit`**, не в `src/cf`.
- Тестовый объект — **новый** общий модуль расширения (не заимствование), как в [первом тесте YAxUnit](https://bia-technologies.github.io/yaxunit/docs/getting-started/first-test/).
- Имя модуля: **`ОМ_<ИмяТестируемогоОбъектаБезПрефиксаПбп>`**.  
  Пример: для `пбп_СтроковыеФункцииКлиентСервер` → `ОМ_СтроковыеФункцииКлиентСервер`.  
  Не использовать суффикс `_Тесты` и префикс `пбп_` в имени тестового модуля.

Существующие наборы: `ОМ_КоннекторHTTP`, `ОМ_ПредопределенныеЗначения`, `ОМ_СтроковыеФункцииКлиентСервер` и др.

## Свойства общего модуля теста (PSSL)

Тестовые модули в этом репозитории — **серверные** (прогон YaXUnit в Enterprise / серверный контекст).

| Свойство | Значение |
|---|---|
| `Server` | `true` |
| `ExternalConnection` | `true` (как у серверных модулей ядра) |
| `ClientManagedApplication` | `false` |
| `ClientOrdinaryApplication` | `false` (обычные формы не используются) |
| `ServerCall` | `false` (кроме отдельных модулей-обёрток вызова сервера) |
| `Global` / `Privileged` | `false` |

Контекст исполнения конкретного теста при необходимости задаётся API регистрации (`ДобавитьСерверныйТест`, `ДобавитьКлиентскийТест` и т.д.) — см. [регистрацию тестовых методов](https://bia-technologies.github.io/yaxunit/docs/features/test-registration/). Не путать с флагами метаданных исходного клиент-серверного модуля ядра: у теста клиентские флаги остаются выключенными.

## Обязательная точка входа

В модуле должна быть экспортная процедура **`ИсполняемыеСценарии()`** — без неё движок не узнает состав тестов (в платформе нет рефлексии методов). Регистрация — через модуль **`ЮТТесты`**.

Рекомендуемая структура областей:

```bsl
#Область СлужебныйПрограммныйИнтерфейс

Процедура ИсполняемыеСценарии() Экспорт
	// регистрация
КонецПроцедуры

#КонецОбласти

#Область Тесты

// экспортные процедуры тестов

#КонецОбласти
```

## Пример: тесты `ПреобразоватьДатуИзСтрокиПоФормату`

Ориентир в репозитории: `src/cfe/YAXUnit/CommonModules/ОМ_СтроковыеФункцииКлиентСервер`.

### Регистрация набора

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.ДобавитьТестовыйНабор("ПреобразоватьДатуИзСтрокиПоФормату (0_0_0)")
			.ДобавитьТест("ТестДолженПарситьISOБезМиллисекунд")
			.ДобавитьТест("ТестДолженИгнорироватьМиллисекунды")
			.ДобавитьТест("ТестДолженИгнорироватьСуффиксZ")
			.ДобавитьТест("ТестДолженИгнорироватьСмещениеЧасовогоПояса")
			.ДобавитьТест("ТестДолженОбрабатыватьПустыеЗначения")
			.ДобавитьТест("ТестДолженВозвращатьПустуюДатуПриНекорректномISO")
			.ДобавитьТест("ТестДолженКорректноОбрабатыватьМассивРазделителейС3Элементами")
			.ДобавитьТест("ТестДолженВозвращатьПустуюДатуПриБитомВремениБезДаты");

КонецПроцедуры
```

### Типовой тест с утверждениями

```bsl
Процедура ТестДолженПарситьISOБезМиллисекунд() Экспорт

	ИсходнаяСтрока = "2024-01-02T03:04:05";
	ОжидаемаяДата = Дата(2024, 1, 2, 3, 4, 5);

	Результат = пбп_СтроковыеФункцииКлиентСервер.ПреобразоватьДатуИзСтрокиПоФормату(ИсходнаяСтрока, "0_0_0");

	ЮТест.ОжидаетЧто(ТипЗнч(Результат)).Равно(Тип("Дата"));
	ЮТест.ОжидаетЧто(Результат).Равно(ОжидаемаяДата);

КонецПроцедуры
```

Правила утверждений в PSSL:

- Для типа значения использовать **`ТипЗнч(Результат)`**, не `Тип(Результат)` (иначе ошибка «Тип не определен»).
- Цепочки утверждений — через **`ЮТест.ОжидаетЧто(...)`** ([документация возможностей](https://bia-technologies.github.io/yaxunit/docs/features/)).
- В 25.x для «пусто» канон — **`НеЗаполнено()`**; `Пусто()` — только алиас совместимости.

### Параметры теста (как в YAxUnit)

Параметры передаются **позиционно** в `.СПараметрами(...)`, а не структурой в одном аргументе:

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.ДобавитьТест("Сложение")
			.СПараметрами(2, 3, 5)
			.СПараметрами(2, -3, -1);

КонецПроцедуры

Процедура Сложение(ПервыйОперанд, ВторойОперанд, ОжидаемыйРезультат) Экспорт

	ЮТест.ОжидаетЧто(ПервыйОперанд + ВторойОперанд).Равно(ОжидаемыйРезультат);

КонецПроцедуры
```

Подробнее: [первый тест](https://bia-technologies.github.io/yaxunit/docs/getting-started/first-test/), [регистрация](https://bia-technologies.github.io/yaxunit/docs/features/test-registration/).

## Что покрывать

- Успешный сценарий (happy path).
- Пограничные и «битые» входы (пустые значения, некорректный формат) — ожидаемое безопасное поведение API.
- Регрессии по известным дефектам (например, ISO с миллисекундами, `Z`, смещением зоны, тремя частями времени `ЧЧ:ММ:СС`).
- Не называть серверные тесты «веб-клиентскими», если они не исполняются в веб-контексте.

## Запуск

- Интерактивно: подсистема YAxUnit в 1С:Предприятие ([запуск и отладка](https://bia-technologies.github.io/yaxunit/docs/getting-started/run/)).
- Пакетно: Unica `test` / `yaxunit` по `tools/yaxunit.json` или фильтр модуля вида `ОМ_СтроковыеФункцииКлиентСервер` (без префикса `CommonModule.` в фильтре YaXUnit, если раннер не находит набор).

После изменения BSL расширения: отдельный `build` source-set `YAXUNIT`, затем прогон тестов.

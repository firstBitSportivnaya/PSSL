# pssl-library — ядро ПБП в этом репозитории

Факты проекта, запреты и правила BSL — `AGENTS.md`. Здесь — инструменты и прогоны локального Cursor с user MCP.

Контракт Unica — `v8project.yaml` (в Git). ИБ и платформа — `v8project.local.yaml` и `.dev.env`. `cwd` в вызовы Unica 0.13 не передавать: рабочее пространство задаёт корень MCP.

## Правки

- XML форм и метаданных — Unica leaf (`form-edit`, `meta-edit`). Поиск — `unica_search` (`corpus: "names"` для объекта, `corpus: "text"` для модуля).
- Правка BSL — `unica_apply` (leaf `code-patch`): план `at` + `ops`, затем только `executionToken`. Не `StrReplace` / `Write` / `Shell` по `src/cf/**/*.bsl` и `src/cfe/YAXUnit/**/*.bsl`, пока `user-unica` готов. `code.replace` — только `….Method.<Имя>.Body`. Замена узла `Method` целиком даёт `postcondition_failed` (repeat-noop), токен не исполнять; описание над процедурой так не меняется. `code.insert` в тело модуля дописывает текст после последней `#КонецОбласти`.
- После правки BSL: `unica_check` по адресу модуля (набор `YAXUNIT` для тестов); если Unica недоступен — LS. Затем Напарник `check_1c_code` → `review_1c_code`, без двойного синтаксиса на одном файле.
- `cwd` не передавать: рабочее пространство — корень MCP этой сессии.

## Загрузка в ИБ

Прогон — фаза тестировщика в `pssl-pr-flow`, в той же сессии сразу после записи запрошенного объёма в исходники или после законченного круга правок. Пока код ещё пишется, базу не обновлять и тесты не запускать. Отдельную фразу пользователя не ждать. Основная конфигурация — каталог `src/cf`, source-set `main`. Расширение — `src/cfe/YAXUnit`, source-set `YAXUNIT`. Каждый изменившийся source-set — своим `push`; без изменений повторно не грузить. YaXUnit — если менялась основная конфигурация или расширение YAXUNIT. Фичи Vanessa — если менялась основная конфигурация или `features/`.

1. Исключение к user rule `ui-testing-tools` (не завершать `1cv8` / `1cv8c`): Designer занимает файловую базу эксклюзивно. Перед `push` закрыть только сеансы, у которых `/F` совпадает с `INFOBASE_PATH`. После загрузки Vanessa MCP поднимать снова по `ui-testing-tools`.
2. Словарь — `unica_run` без `op`. Для каждого изменившегося source-set: `op=push`, `args.sourceSet=<main|YAXUNIT>`, сначала верхний `dryRun=true`, затем тот же вызов с верхним `dryRun=false`. `dryRun` в `args` не класть: `push does not accept dryRun`. Если менялись оба — сначала `main`, затем `YAXUNIT`. Неизменившийся source-set не грузить. `args.full=true` — только после переключения ветки, rebase, merge `origin/develop`, крупного переноса объектов или подозрения на испорченное инкрементальное состояние. `args.force=true` перезаписывает базу и затирает изменения, сделанные в ней: только после явного решения. Отказ `non_fast_forward`, `no_memory` или `invalid_state` (поколение базы впереди записи раннера, текст `infobase moved ahead`) — стоп, не автоматический `force`. В `push` передавать `sourceSet`, не `extension`. Не один `push` «на все расширения».
3. Долгий вызов становится задачей. Хранить `taskId`. Состояние — `unica_task_get`, ожидание — `unica_task_result` (`waitMs` не больше 7000). `working` не доказывает прогресс и не повод для второго `push`.
4. Итог source-set — завершённая задача без ошибки и строка «Обновление конфигурации успешно завершено» в журнале платформы, который назвал ответ. Тот же `push` повторно не запускать.

Не вызывать снятые `unica_build_*` и `unica_runtime_*`. Прямой `v8-runner.exe` — только прогон YaXUnit из раздела ниже. `push`, `pull` и остальные операции раннера через бинарник не вызывать: они остаются на `unica_run`. `upload` на v0.13 недоступен. `launch` для Vanessa не вызывать.

После загрузки основная конфигурация обновляет конфигурацию базы без `-Extension`, расширение — с `-Extension YAXUNIT` (не безопасный режим). Это делает `push`: отдельный `/UpdateDBCfg` не сочинять.

### Сбои задания

- Отказ обхода каталога исходников на облачном диске («Отказано в доступе»): если ответ назвал журнал платформы — итог судить по нему. `1CD` не удалять, takeown не вызывать.
- Файл `.unica-apply-*` рядом с `Module.bsl` в `Ext` (после `unica_apply`) на облачном диске может стать нечитаемым (`os error 5`). Сухой `push` при этом ещё может построить план из кэша, а исполнение падает `provider_failed` / `hard storage error` на обходе source-set, до платформы: журнала конфигуратора нет, база не менялась. Второй `unica_apply` не начинать. Файлы `.unica-apply-*` удаляет человек, затем тот же `push` повторить. Сам `Module.bsl` при этом читается.
- Задача остаётся `working` дольше ожидаемого окна: читать `unica_task_get`. `unica_task_cancel` — просьба, не подтверждение остановки. Пока раннер или `1cv8` этой базы жив — ждать. Не удалять `.build/unica/jobs/active.lock`: это файл Unica 0.12, v0.13 его не использует. Успешный шаг не повторять. После перезапуска демона `outcome_uncertain` значит, что загрузка могла примениться: смотреть базу и журнал, не запускать второй `push` вслепую.

## YaXUnit — написание

Канон: `docs/РуководствоПоНаписаниюТестовYAxUnit.md` + [features](https://bia-technologies.github.io/yaxunit/docs/features). Дизайн тестов Unica `test-authoring` — общее; пины и запуск — здесь.

- Модуль теста: `ОМ_<Объект>` (один `_` после `ОМ`; существующие: `ОМ_ПредопределенныеЗначения`, `ОМ_КоннекторHTTP`, …).
- Экспорт `ИсполняемыеСценарии()` — только регистрация через `ЮТТесты` (`ДобавитьТестовыйНабор` / `ДобавитьТест` / `СПараметрами` / `ВТранзакции`); без создания данных в этой процедуре.
- Утверждения и данные: `ЮТест.ОжидаетЧто(...)`, `ЮТест.Данные()`, при необходимости `ЮТест.Варианты` / `ЮТест.Предикат` / `Мокито`.
- В новых тестах `НеЗаполнено()`, не `Пусто()` (алиас совместимости 25.x).
- Флаги `ОМ_*` для пакетного прогона: обычно `Server=true`, `ExternalConnection=true`; клиентские флаги — только если тест реально клиентский. `ДобавитьКлиентскийТест` выбирает клиентский контекст лишь среди доступных модулю по метаданным; `Server` сам по себе клиент не даёт.

## YaXUnit — запуск

Только фаза тестировщика `pssl-pr-flow` или явная просьба пользователя. `dryRun=true` у `push` прогоном тестов не считать. Сначала раздел «Загрузка в ИБ».

Прогон — вложенный `v8-runner` поставки Unica, не `unica_run` и не ручной `1cv8c`. В словаре `unica_run` 0.13 операции test нет: `op=test` даёт `unsupported_operation`. Бинарник — `v8-runner.exe` в `%LOCALAPPDATA%\IngvarConsulting\unica\runtimes\v8-runner\` (каталог версии внутри кэша Unica, не отдельная установка). Рабочий каталог — корень репозитория: подхватываются `v8project.yaml` и `v8project.local.yaml`.

Команда из корня:

`v8-runner.exe --json-message --no-color test yaxunit all --no-push`

- `--no-push` — база уже загружена через `push`. Без этого ключа раннер снова шлёт исходники. У команды нет предпросмотра: `--dry-run` отвечает `invalid_argument`.
- Охват — `all`. `test yaxunit module` не использовать. На движке 25.12 фильтр `CommonModule.ОМ_…` кладёт в ключ точку, `ЮТКоллекции` отвечает «Задано неправильное имя атрибута структуры», дальше зацикливание. Модули `ЮТ*` не патчить.
- `--full` у `test yaxunit all` только разворачивает обрезанный стек. Это не полная перезагрузка базы.
- JSON писать в файл UTF-8 и читать его. Перехват консоли PowerShell 5.1 портит кириллицу. Пути базы и пароль из конверта в ответ не копировать.

Итог — этот JSON, не `tools/yaxunit.json` и не код выхода предприятия. Зелёный прогон: верхний `ok` истинно, `data.report.summary.total` больше нуля, `failed` и `errors` равны нулю. Падения тестов: `ok` ложно, `data.error_kind` равен `test_failures`, имена и тексты — в `data.report.suites`. Шаг `run` при этом может сказать `enterprise exit code 0`, а конверт — `runtime_failure`: код выхода предприятия зелёным не считать. Строк `Tests completed` в отчёте нет. `logging` в `tools/yaxunit.json` ради прогона не включать.

Протокол сессии — user rule `ui-testing-tools` и skill `vanessa-automation`. Старт — общий `Start-VanessaMcp.ps1 -RepoRoot` (корень клона). Живой MCP — `tools/VAParams.json` (`ВыполнитьСценарии` = false), CI — `tools/VBParams.json`. Фичи — через Vanessa MCP, не через Unica. Не использовать Vanessa MCP для фактов конфигурации (это Unica).

## Vanessa — написание фич (PSSL)

Дополняет skill `vanessa-automation` (шаги и MCP). Отличия Jenkins — `.cursor/rules/vanessa-jenkins.mdc` (единственный источник). Здесь — каталог и приёмы этого репозитория.

Эталон в репозитории: `features/Создание и пометка на удаление настройки отбора объектов.feature`. Шаги не выдумывать — копировать оттуда и из `search_for_steps_by_keywords`.

- Каталог `features/`. Порядок прогона — `СписокФичДляВыполнения` в `tools/VBParams.json`; тот же массив в `tools/VAParams.json`. Новую фичу добавлять в конец обоих списков, существующие строки не переставлять. Новую фичу класть на ветку PR, не в `develop` «заодно». Прогон MCP — `run_scenario` в этом порядке.
- Каждый **сценарий** самодостаточен: сам ищет и чистит свои данные, сам создаёт ссылки. Не открывать элемент, созданный предыдущим сценарием (CI может прогнать один сценарий).
- Имена `ВА_…`, уникальные на сценарий (`ВА_PR376_Очистка`, не одно имя на всю фичу).
- Очистка: `ФормаНайти` (FieldSelector «Наименование», не CompareType) → «По точному совпадению» → `пока в таблице "Список" количество строк ">" 0`. Если текущая строка **уже помечена на удаление** — `я прерываю цикл` (иначе `я удаляю строку` часто не открывает `1С:Предприятие`). Непомеченные: `я меняю пометку удаления строки` и `Button0`. Не заменять это на одиночный `Если в таблице есть строка` — при перезапуске остаются дубли.
- Выбор после очистки: последняя строка поиска и `текущая строка не помечена на удаление`.
- Заголовок списка = ListPresentation (`Настройки интеграции`), форма элемента = ObjectPresentation (`Настройка интеграции (создание)`). Не подставлять заголовок списка в окно создания.
- Перед `ФормаЗаписатьИЗакрыть` заполнить обязательные поля. Пометка удаления / «1С:Предприятие» — `Button0`; вопрос формы (`Да`/`Нет`) — по заголовку кнопки.
- «Кнопка не найдена» или «недоступный элемент»: сначала `unica_view` адреса формы и ветви `Item` (элемент Button, родитель, видимость). Кнопка — элемент Button, не запись в командах. Команда без кнопки и панель таблицы с `CommandBarLocation` `None` кликом не лечатся; видимые команды — на командной панели формы. Текущий `view` не отдаёт `CommandName`: связь команды с кнопкой проверять по XML формы через `unica_resolve`, если ветви `Item` недостаточно. `close_function_panel`, `УстановитьПривилегированныйРежим` и выдача ролей — только когда кнопка в форме уже есть.
- После правки: `open_feature_file` → `load_features` → `check_syntax` → `run_scenario` изменённых сценариев. Без зелёного прогона фича не готова. Если сценарий пишет справочники — прогнать фичу **второй раз**.
